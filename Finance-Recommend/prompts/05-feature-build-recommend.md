아래 기능을 MVP 범위 안에서 구현해줘.

## 구현할 기능
- 기능명: 조건 기반 ETF 추천 (추천 버튼) — 기능 분해표 F-01·F-04·F-06·F-09 범위
- 기능 설명: 사용자가 [추천] 버튼을 누르면 입력 조건으로 ETF를 필터링하고,
  점수순으로 정렬해 추천 결과와 근거·적용 상태를 함께 보여준다.
  필터·순위·설명 기준은 `docs/function-breakdown.md` 2장(기능 분해표)의
  F-04(적격 후보 필터)·F-06(조건 비교·점수 설명·정렬)과
  `docs/mvp-plan.md` 3.1(성향별 점수 규칙)을 따르되,
  아래 "예외 처리 규칙"에 적힌 항목은 이 문서를 우선한다.
- 사용자 입력 (`POST /api/recommendations` 요청 본문):
  - budgetKrw: 예산(원, 정수, 필수, 0보다 커야 함)
  - industries: 산업(다중 선택, 허용 목록 안의 값만, 선택 안 하면 전체)
  - resultCount: 결과 개수(선택, 기본 5, 1~20)
  - riskProfile: 투자 성향(선택, 기본 "중립형", 허용값 안정형/중립형/공격형)
    → 2장 F-06의 성향별 가중치를 적용하기 위해 필요
- 처리 방식:
  1. 입력 검증: 실패 시 필드별 오류 메시지를 반환하고 중단(후보 계산·로드 호출 안 함)
  2. 필터 (2장 F-04 기준):
     a. 데이터 부족: 가격 결측 종목 제외, 산업 필터 사용 시 산업 결측("기타") 종목 제외
     b. 예산: 1주 가격 ≤ 예산
     c. 산업: 선택 산업 중 하나라도 속하면 통과(OR), 미선택이면 전체 통과
  3. 점수 계산 (2장 F-06 기준):
     - 지표: 과거 수익률(높을수록 좋음), 변동성(낮을수록 좋음), 최대 낙폭(낮을수록 좋음)
     - 각 지표를 필터 통과 후보군 안에서 0~100 백분위 호감도로 변환(동점은 평균 순위)
     - 성향별 가중치(수익률/변동성/최대 낙폭):
       안정형 20/35/45, 중립형 35/30/35, 공격형 55/20/25
     - 총점 = Σ(지표 호감도 × 가중치), 소수 둘째 자리 반올림
  4. 정렬: 총점 내림차순, 동점이면 아래 동점 규칙을 따름
  5. 설명 생성: 종목별 통과 필터, 지표별 점수 기여(원값·호감도·적용 가중치·기여 점수),
     적용된 예외 규칙(결측 보정·동점 처리 여부)
  6. 결과 반환: resultCount개까지 자르고, 상단 요약과 함께 반환
- 예외 처리 규칙:
  - 예산 경계: 가격 = 예산이면 포함(이하 기준), 1주 가격 기준, 수수료·세금 제외
  - 결측(필터 항목):
    - 가격 결측 → 항상 제외, 사유 "데이터 부족"
    - 산업 결측 → "기타"로 간주. 산업 필터를 쓰면 제외(사유 "데이터 부족"),
      산업 미선택이면 포함
  - 결측(점수 항목): 결측 지표는 빼고 남은 지표 가중치를 합이 100%가 되도록 재정규화,
    결과에 "일부 지표 결측" 표시와 결측 지표명 기록.
    예) 중립형에서 수익률 결측 → 변동성 30/65(46.15%), 최대 낙폭 35/65(53.85%)
    세 지표가 모두 결측이면 점수를 만들 수 없으므로 제외, 사유 "데이터 부족"
  - 백분위 계산 대상이 1개뿐인 지표는 호감도 50으로 두고 "상대 비교 불가"를 기록
  - 동점: 총점 → 시가총액 큰 순(결측은 뒤) → 종목코드 오름차순
    (같은 입력·같은 데이터면 항상 같은 순서). 동점 규칙이 실제로 순서를 정한
    종목에는 "동점 처리: 시가총액" 또는 "동점 처리: 종목코드"를 표시
  - 산업 조건: 다중 선택은 OR, 미선택은 전체.
    산업 분류가 없는 종목은 "기타"로 보고, 산업 필터를 쓰면 제외.
    "기타"는 사용자가 선택할 수 있는 값이 아님
  - 결과 0건: 빈 목록과 함께 "조건에 맞는 종목 없음" 메시지,
    그리고 가장 많이 걸러낸 조건(조건명·건수)을 반환
  - 제외 사유 집계: 요약의 "제외 사유별 건수"는 처음 걸린 필터 1개로만 집계
    (순서: 데이터 부족 → 예산 → 산업, 합계 = 제외 건수).
    "가장 많이 걸러낸 조건"은 각 조건을 전체 종목에 독립 적용했을 때 탈락 건수가
    가장 많은 조건, 같으면 위 필터 순서가 앞선 조건
- 출력 결과:
  - 상단 요약: 적용된 예산·산업 조건·투자 성향·결과 개수, 전체/통과/제외 건수,
    제외 사유별 건수, 데이터 기준일·출처, 결과 0건이면 메시지와 가장 많이 걸러낸 조건
  - 추천 목록(종목별): 순위, 종목명·코드, 가격, 산업, 총점,
    지표별 점수 기여, 통과한 필터, 적용된 예외(결측 보정·동점 처리 여부)
  - 고정 안내 문구: "이 결과는 입력하신 조건에 따른 ETF 후보 비교 정보입니다.
    과거 성과는 미래 수익을 보장하지 않습니다."

## 구현 기준
- 기존 프로젝트 구조를 먼저 확인해줘. (angel_ETF/docs/project-structure.md의 모듈 경계를 유지)
- 관련 파일을 읽고 필요한 파일만 수정해줘. 위 "건드리지 않음" 파일은 수정하지 마.
- 한 번에 전체 시스템을 만들지 말고 이 기능에 필요한 최소 범위만 구현해줘.
  (KRX 수집, DB, 결과 저장·재조회, 7일 만료, 로그인, 캐릭터형 UI는 만들지 마)
- router, schema, service 역할을 분리해줘.
  - router: 추천 요청을 받고 service 호출 결과를 응답으로만 반환
  - schema: 입력(예산·산업·개수·성향)과 출력(요약·목록·근거) 구조 정의, 입력 검증
  - service: 필터 → 점수 → 정렬 → 설명 생성 로직 (FastAPI에 의존하지 않는 순수 함수로)
- 필터 순서·점수 가중치·동점 기준·결과 개수 기본/최대·산업 허용 목록은
  core/config.py 상수로 분리해서 나중에 바꾸기 쉽게 해줘.
  산업 허용 목록 초안: 반도체, 2차전지, IT, 금융, 헬스케어, 에너지, 소비재, 채권
- 같은 입력이면 항상 같은 결과가 나오게 해줘(정렬 키 고정, 부동소수 비교는 반올림 값 사용).
- 실제 API Key, token, password는 코드에 직접 작성하지 말아줘.
  이 기능은 .env와 KRX 키를 읽지 않는다. .env 파일을 열거나 출력하지 마.

  1. 정상 입력 → 점수순 결과와 근거 표시
     (예: 예산 50000, 산업 미선택, 중립형 → 총점 내림차순, 종목마다 지표별 기여·통과 필터 존재)
  2. 가격 = 예산인 종목 → 포함되는지 (가격 50000 / 예산 50000 포함, 50001은 "예산" 사유로 제외)
  3. 가격·산업 결측 종목 → 제외되고 사유 "데이터 부족"이 기록되는지
     (가격 결측은 항상, 산업 결측은 산업 필터 사용 시)
  4. 점수 지표 일부 결측 → 재정규화되고 "일부 지표 결측"이 표시되는지
     (적용 가중치 합 = 100%, 결측 지표 기여 = 0, 세 지표 모두 결측이면 "데이터 부족" 제외)
  5. 동점 종목 → 시가총액 → 종목코드 순으로 정렬되는지, 동점 처리 표시가 붙는지
  6. 산업 미선택(전체·"기타" 포함) / 다중 선택(OR) / 분류 없음("기타", 필터 사용 시 제외) 처리
  7. 예산 0 또는 음수 → 오류 처리(422, 필드별 메시지, 후보 계산 안 함).
     resultCount 0·21, 허용 목록 밖 산업·성향도 함께 확인
  8. 결과 0건 → "조건에 맞는 종목 없음" 메시지와 가장 많이 걸러낸 조건 표시
  추가: resultCount보다 후보가 많으면 그 개수까지만, 같은 요청 2회 결과가 동일한지
