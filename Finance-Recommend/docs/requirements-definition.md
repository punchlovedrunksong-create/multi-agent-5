### 후보 적격성과 비교 기준

- 후보 ETF의 기준 가격이 투자금 이하이면 “1주 이상 매수 가능 후보”로 분류한다. **[가정]** 거래 수수료·세금은 현재 필터에서 계산하지 않는다. 포함 여부는 [확인 필요].
- 투자 기간은 성과 관측 기간 및 위험 해석에 반영한다. 단기·중기·장기 구분의 구체적 계산 기간은 [확인 필요].
- 선호 산업·테마는 일치 근거를 표시하고, 제외 산업 조건과 충돌하는 ETF는 후보에서 제외하는 방향으로 설계한다. 제외 판정 기준과 산업 노출 임계값은 [확인 필요].
- 투자 성향은 안정형·중립형·공격형으로 구분한다. MVP의 비교 점수 기본 가중치는 안정형(수익률 20%, 변동성 35%, 최대 낙폭 45%), 중립형(35%, 30%, 35%), 공격형(55%, 20%, 25%)으로 둔다. 이 수치는 공개된 표준 가중치가 아닌 V1의 설명 가능한 제품 규칙이며 수익률만으로 후보를 정렬하지 않는다. 실제 API의 필드·산식·관측 구간을 확인한 뒤 같은 개념의 지표가 제공되는지 매핑한다. 제공되지 않는 지표는 추정하지 않는다.
- 투자 기간은 가용 데이터에서 해당 기간에 가장 잘 맞는 관측 구간을 선택하는 데 사용한다. 기간별 자료를 제공할 수 있는지 KRX API 연결 후 확인하고, 비교 기간을 맞출 수 없으면 그 한계를 표시한다. 투자 기간만으로 수익이나 적합성을 보장하지 않는다.
- **기본안:** 조건 일치 점수 기준 상위 5개 후보를 표시한다. 점수의 세부 배점·동점 처리·후보가 5개 미만일 때의 화면은 [확인 필요].
- 모든 시장 데이터에는 기준일시·출처·갱신 상태를 함께 저장하고 표시한다. 제공되지 않은 값은 추정하지 않고 “확인 불가”로 표시한다.

### 사용자가 보는 화면

1. **서비스 소개/조건 입력:** 서비스 범위와 비교 한계를 안내하고 다섯 가지 조건을 입력한다. 필수값 누락, 음수 투자금, 유효하지 않은 선택값을 즉시 표시한다.
2. **후보 목록:** 적용 목표와 입력 조건을 요약하고, 투자금으로 1주 이상 살 수 있으며 제외 조건을 통과한 ETF를 조건 일치 점수 순으로 최대 5개 표시한다. 결과가 적으면 적은 수 그대로 보여준다.
3. **후보 비교:** ETF마다 개성 있는 안내 캐릭터가 있는 비교 카드를 보여준다. 캐릭터는 이해를 돕는 표현이며 투자 성향이나 상품 위험을 의인화해 단순화하지 않는다. 카드에 가격, 투자 기간별 성과, 변동성, 최대 낙폭, 선호/제외 조건 판정, 추천 이유, 점수 근거, 데이터 기준일·출처와 결과 해석 안내를 표시한다. 사용자가 비교에 담은 후보는 캐릭터 카드형 비교 패널에서 나란히 본다.
4. **ETF 상세:** ETF 코드·명, 기본 정보, 기준 가격, 위험·성과 지표, 산업·테마/노출 근거, 데이터 출처와 갱신 시각을 보여준다.
5. **최근 결과:** 저장된 비교 결과와 당시 입력 조건을 1주일 동안 조회한다. 접속 식별 방식(로그인/익명 세션)과 기기 간 조회는 [확인 필요].
6. **데이터 안내:** API 지연·오류·누락, 후보 없음, 지원되지 않는 산업/테마를 구체적으로 안내하고 조건 수정 또는 다시 시도 방법을 제공한다.

### Backend 기능

- 입력값의 타입·범위·허용 목록을 검증하고 잘못된 입력에 필드별 오류를 반환한다.
- KRX API 인증 정보를 서버 측에 보관하고, 프런트엔드 코드·응답·로그에 노출하지 않는다.
- 수집 작업의 주기·재시도·중복 적재 방지·변경 이력·마지막 성공 시각을 관리한다. 주기와 재시도 횟수는 [확인 필요].
- 원천 데이터를 정규화하고, 출처·기준일이 연결된 데이터만 후보 필터와 지표 계산에 사용한다.
- 투자금 적격 필터, 산업/테마 조건 필터, 위험/성과 지표 산출, 조건 일치 점수 및 상위 후보 조회를 수행한다.
- 요청 입력의 조건 스냅샷, 결과 후보, 각 점수 근거, 계산 버전, 원천 데이터 버전을 보관한다.
- 저장 만료 1주일 후 결과 레코드 및 입력 스냅샷을 자동 삭제하고, 수동 조기 삭제 지원 여부를 [확인 필요]로 둔다.
- 실패 상태를 구분한다: KRX 호출 실패, 인증/호출 한도 오류, 오래된 데이터, 지표 계산 불가, 조건에 맞는 후보 없음.

### DB 논리 구조 요구사항

DB 기술과 물리 스키마는 아직 확정하지 않고, MVP에 필요한 논리 데이터 집합을 정의한다.

| 논리 엔터티 | 주요 필드 예시 | 관계·목적 |

| 7 | 결과 저장·출력 | 최대 5개 후보와 근거를 화면에 표시하고, 조건 스냅샷·데이터 기준·결과를 1주일 보관한다. |
| 8 | 만료·운영 점검 | 만료 결과를 삭제하고 API 수집 이력과 오류를 운영 화면에서 확인한다. |

## 8. 출력 결과

| 출력 결과 | 형식 | 설명 |
| --- | --- | --- |
| 추천 목표·적용 조건 요약 | 결과 상단 요약 카드 | 사용자가 입력한 투자금·투자기간·선호/제외 산업·테마·투자성향을 표시하고, 이번 결과가 “조건에 맞는 ETF 후보 비교”를 위한 것임을 밝힌다. 별도 목표 수익률은 입력값으로 확정되지 않았으므로 목표 수익률로 해석하거나 제시하지 않는다. |
| ETF 후보 목록 | 안내 캐릭터가 포함된 정렬 카드, 최대 5개 | 투자금으로 1주 이상 매수 가능하고 제외 조건을 통과한 ETF |
| 핵심 지표 | 후보별 수치 카드·비교표 | 기준 가격, 투자기간에 맞춘 과거 수익률, 변동성, 최대 낙폭. 각 지표에 산식/관측 구간·기준일·출처를 붙인다. 확인할 수 없는 값은 “확인 불가”로 표시한다. |
| 추천 이유 | 캐릭터 설명, 조건별 근거 문장·배지 | 캐릭터가 후보를 소개하되 투자금 적격, 투자기간 적합도, 선호 산업/테마 일치, 성향 대비 위험 지표를 각각 근거와 함께 설명한다. 캐릭터의 성격을 추천 점수나 위험 수준의 대체 표현으로 쓰지 않고, 미확인 분류를 일치로 단정하지 않는다. |
| 결과 해석·안내 | 결과 상단/하단 안내문 | 조건 점수의 의미와 한계, 수익률·위험 지표의 관측 구간, 데이터 누락 여부를 알려준다. 과거 성과가 미래 성과를 보장하지 않으며 이 결과는 후보 비교 정보라는 안내를 포함한다. |
| 후보 상세 | 상세 정보 패널 | ETF 기본정보, 가격, 지표, 기초지수·산업/테마 정보의 출처와 기준일 |
| 저장된 결과 | 이력 목록/상세 | 당시 입력 조건, 후보 순위·근거, 데이터 기준 버전, 만료 시각 |
| 상태 메시지 | 입력 검증/로딩/완료/부분 결과/빈 결과/오류 배너 | 현재 처리 상태, 사용할 수 없는 데이터, 마지막 성공 기준일과 재시도·조건 수정 등 가능한 다음 행동을 표시한다. API 장애와 정상적인 빈 결과를 구분한다. |
| 사용자 안내 문구 | 필드 도움말, 툴팁, 경고·안내문 | 입력 방법, 투자금에 따른 1주 가격 조건, 지표 정의, 데이터 출처·시점, 투자 결과의 한계를 쉬운 문장으로 알려준다. |
| 후보 비교 패널 | 캐릭터형 카드 묶음 | 사용자가 선택한 후보를 캐릭터·ETF명·가격·수익률·변동성·최대 낙폭·조건 어울림 근거로 나란히 비교한다. 표만으로 결과를 제공하지 않는다. |

### 상태 메시지 및 안내 문구 예시

문구는 화면 설계 시 확정할 초안이다. API 오류 문구에는 인증키나 내부 시스템 상세정보를 노출하지 않는다.

| 상태 | 표시 문구 예시 | 다음 행동 안내 |
| --- | --- | --- |
| 입력 검증 오류 | “투자금은 0보다 큰 금액으로 입력해 주세요.” | 입력 필드를 강조하고 유효한 값 입력 안내 |
| 후보 조회 중 | “입력하신 조건으로 ETF 후보와 비교 지표를 확인하고 있어요.” | 중복 요청을 막고 로딩 상태 표시 |
| 결과 완료 | “조건에 맞는 후보를 찾았습니다. 각 ETF의 가격과 지표 기준일을 확인해 주세요.” | 후보 비교와 상세 보기 제공 |
| 일부 지표 확인 불가 | “일부 ETF 지표를 확인할 수 없어 완전한 기준으로 비교되지 않을 수 있습니다.” | 누락된 지표와 점수/정렬에 미치는 영향을 명시. 영향 기준이 미확정이면 점수 순위를 확정값처럼 표현하지 않음 |

| 데이터 오래됨 | “표시된 데이터는 최신이 아닐 수 있습니다. 기준일을 확인해 주세요.” | 데이터 기준일 표시, 새로고침 가능 여부 안내 |
| 결과 만료 | “저장된 결과의 보관 기간(1주일)이 끝났습니다.” | 새 조건으로 다시 비교하도록 안내 |
| 결과 해석 안내 | “이 결과는 입력하신 조건에 따른 ETF 후보 비교 정보입니다. 과거 성과는 미래 수익을 보장하지 않습니다.” | 매수 권유가 아닌 정보 비교 결과임을 명확히 표시 |

## 제약과 데이터 취급

- 입력 형식은 원화 투자금, 사전 정의한 기간·성향 선택값, 산업·테마 다중 선택값으로 제한한다. 금액 최대값, 지원 분류 개수와 입력 길이는 [확인 필요].
- KRX 인증키는 Backend에서만 사용한다. 저장소·프런트엔드·일반 로그·오류 응답에 인증키를 기록하지 않는다.
- 시장 데이터는 데이터 라이선스와 API 이용 조건이 확인된 범위만 저장·표시한다. 재배포나 상업적 서비스 가능성을 사전 확인한다.
- 추천 조건과 결과 스냅샷은 7일 후 만료·삭제한다. **[가정]** 1주일 보관 기간은 생성 시각 기준 7×24시간으로 해석했다. 사용자가 말한 “1주일”의 달력 기준 여부가 다르면 조정한다.
- 추천 요청에 포함된 투자금·성향·선호/제외 조건은 결과와 연결된 민감 가능 데이터로 취급하고 최소한의 접근·로그만 허용한다. 사용자별 인증과 익명 세션 중 어느 방식을 쓸지는 [확인 필요].
- 추천은 입력값과 기록된 데이터 기준에 따라 생성하며, 매수 지시나 수익 보장으로 표현하지 않는다. 과거 성과는 미래 수익을 보장하지 않는다.
- API 제공 지연·시장 휴장·장중/종가 등 시세 기준을 화면에 명시한다. 실시간 제공 여부를 확정하지 않는다.

## [가정]·[규제]·[후순위] 표시

- **[가정]** 일반 개인 투자자를 1차 사용자로 보고, 웹 서비스에서 조건 비교와 결과 이력을 제공한다.
- **[가정]** 투자 기간 4구간, 투자 성향 3단계(안정형/중립형/공격형), 비교 지표 3종, 최대 5개 후보를 사용한다. 기본 성향별 점수 가중치는 MVP 규칙으로 정하고 API 필드 확인 후 매핑한다.
- **[가정]** “1주일”은 추천 결과 생성 시각부터 7×24시간으로 계산한다.
- **[확인 필요]** API에서 제공하는 필드·성과 관측 구간·위험 지표 산식, ETF 분류와 산업 노출 기준·가격에 수수료를 반영할지 확인한다. 성향별 기본 비교 가중치는 MVP 규칙을 따른다.
- **[규제]** 자본시장법은 투자자문업을 금융투자상품 가치 또는 투자판단에 관한 자문에 응하는 영업으로 정의한다. 사용자가 후보 비교만을 선택했더라도 개인 조건 기반 후보 순위·설명 방식이 규제상 어떤 취급을 받는지 출시 전 법률 검토가 필요하다. 이 문서는 적법성 판단이 아니다. [자본시장법 제6조](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1035145039)
- **[규제]** KRX Open API 목록에는 ETF 일별매매정보 서비스가 있으며, 데이터 수신 안내는 개인의 단순 참고 목적과 데이터 재배포·수익사업 활용을 구분한다. 실제 서비스 목적·수익모델·표시 방식에 필요한 이용 승인·계약·라이선스를 확인해야 한다. ETF 테마·기초지수·구성종목 등 모든 추천 필드가 KRX API로 제공된다고 단정하지 않는다. [KRX Open API 서비스 목록](https://openapi.krx.co.kr/contents/OPP/INFO/service/OPPINFO004.cmd), [KRX 데이터 수신방법](https://openapi.krx.co.kr/contents/OPP/DATA/OPPDATA003.jsp)
- **[규제]** 투자금·성향·선호 조건과 이력은 개인을 식별하는 정보와 결합되는 경우 개인정보 또는 금융 관련 정보가 될 수 있다. 처리자 역할, 고지·동의·위탁·국외 이전 및 삭제 요건을 개인정보/금융 분야 전문가와 확인한다. [개인정보 보호법](https://law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029335625), [신용정보법](https://www.law.go.kr/lsInfoP.do?lsId=001540)
- **[후순위]** 증권사 계좌 연동·주문, 실시간 시세, 생성형 대화, 자산 전체 최적화, 기기 간 로그인 이력 조회는 MVP 밖이다.
