## 1. 프로젝트 개요

| 항목 | 내용 |
| --- | --- |
| 프로젝트명 | angel ETF |
| 한 줄 설명 | 사용자의 조건과 정량 지표로 ETF 후보 순위·선정 이유를 보여주고, V2에서는 추천 카드에서 해당 ETF와 직접 관련된 기사를 확인하고 원문을 열 수 있는 웹 서비스 |
| 프로젝트 목표 | V1의 정량 기준 ETF 후보·점수·순위를 유지하면서, 추천된 ETF별 직접 관련 기사를 별도 정보로 제공한다. 뉴스 정보는 V2에서 ETF 후보 적합성·점수·순위에 영향을 주지 않는다. 결과는 정보 비교이며 개별 ETF 매수 지시가 아니다. |
| 개발 기간 | [확인 필요] |
| 팀원 | [확인 필요] |

**대상 사용자 가정:** ETF 기초 정보와 위험 지표를 직접 비교하기 어려운 국내 개인 투자자. V1의 웹 화면·Backend·DB·KRX 데이터 기반을 이어 사용한다. 로그인, 주문, 투자 자문 기능은 이 문서의 범위가 아니다.

## 2. 해결하고자 하는 문제

| 항목 | 내용 |
| --- | --- |
| 현재 문제 | ETF의 가격·성과·위험 지표와 최근 기사를 여러 곳에서 찾아 비교해야 한다. 검색 결과에는 이름이 비슷한 다른 ETF 기사나 ETF를 직접 다루지 않는 기사도 섞일 수 있다. |
| 사용자가 겪는 불편 | V1 순위의 정량 근거를 확인하더라도, 추천 ETF를 직접 다룬 최근 소식인지 사용자가 별도로 검색하고 판별해야 한다. |
| 이 서비스가 제공할 가치 | 정량 기준으로 선정된 ETF 후보와 순위·선정 이유를 유지하고, 각 추천 카드에 해당 ETF를 직접 다룬 기사 제목·발행일·원문 출처 링크를 함께 제공한다. 직접 관련성을 확인할 수 없거나 조회가 실패해도 정량 결과는 볼 수 있게 한다. |

### 정량 지표를 뉴스로 보완하는 이유

수익률·변동성·최대 낙폭은 관측 기간에 ETF 가격이 얼마나 올랐는지, 얼마나 흔들렸는지, 고점에서 얼마나 하락했는지를 비교하는 데 쓰인다. 가격이 움직인 배경이나 지표를 계산한 뒤 발표된 상품 변경은 이 수치만으로 파악하기 어렵다.

예를 들어 최근 1년 수익률과 변동성이 비슷한 두 ETF 중 하나가 추종 지수 변경을 발표했다고 가정하자. 기존 점수가 비슷하더라도 변경이 적용되면 편입 종목과 투자 대상이 달라질 수 있다. 사용자는 추천 카드에 표시된 직접 관련 기사의 원문에서 변경 내용과 적용 시점을 확인할 수 있다. V2는 이 정보를 정량 선정 이유와 함께 제공하고, 동일한 입력과 정량 데이터에서는 V1의 후보·점수·순위를 유지한다(R-04, R-05, R-09~R-11).

### V1 정량 기준 보존 원칙

- 동일한 입력 조건과 동일한 정량 데이터가 주어지면 V1과 같은 후보·정량 점수·순위를 유지한다.
- 뉴스 검색·기사 제목·발행일·출처 링크·Decisions API 판정 결과는 후보 필터, 정량 점수, 정렬 순서, 추천할 다음 후보 결정에 입력하지 않는다.
- 뉴스는 이미 V1 추천 결과에 든 ETF 카드의 부가 정보다. 추천되지 않은 ETF를 뉴스로 새 후보에 올리지 않는다.
- 동명이거나 이름이 유사한 다른 ETF를 다루는 기사, 대상 ETF가 무엇인지 불분명한 기사는 직접 관련 기사로 보여주지 않는다.
- Decisions API의 판정 기준이 불확실/미정이거나 판정 호출에 실패한 기사는 직접 관련으로 간주하지 않는다. 검색·판정 오류는 정상적인 “직접 관련 기사 없음”과 구분한다.

## 6. 사용자 화면, Backend와 DB 요구사항

### 서비스 구성 요소

| 구성 요소 | V2 요구사항 |
| --- | --- |
| 사용자 화면(Frontend) | V1 조건 입력·정량 결과 카드에 ETF별 관련 기사 영역을 추가한다. 기사 상태와 제목·발행일·출처 링크를 구분해 표시한다. 뉴스 조회 실패여도 정량 결과 영역은 보인다. |
| Backend | V1 추천 계산을 먼저 완료하고 그 추천 목록을 뉴스 검색 입력으로 사용한다. 뉴스 검색·관련성 판정은 별도 처리 경로로 수행하며 해당 오류가 추천 계산/응답 전체를 실패시키지 않게 한다. |
| 뉴스 검색 연동 | 추천된 ETF 이름으로 검색한다. 공급자, 인증, 호출 한도, 조회 기간과 검색 결과 계약은 [확인 필요]. |
| Decisions API 연동 | 기사 후보와 목표 ETF의 직접 관련성을 API의 사전 정의 기준에 따라 판정한다. 기준 버전 및 실패 응답을 구별할 수 있어야 한다. 실제 요청·응답 필드는 [확인 필요]. |
| KRX·추천 엔진 | V1 데이터 검증·필터·정량 점수·동점 처리·정렬 규칙을 유지한다. 뉴스 결과를 입력받지 않는다. |
| DB·결과 이력 | V1 데이터 저장 규칙을 유지한다. 뉴스 결과를 영구/임시 저장하거나 이력 화면에서 재사용할지는 [확인 필요]. 저장 시 기사 URL·판정 근거의 이용권 및 보관 기간을 확인한다. |
| 보안·운영 | News provider·Decisions API 인증정보는 서버 측에서만 보관한다. 사용자 투자 조건은 뉴스 검색/판정 API로 보내지 않고, 필요한 ETF 이름·식별자와 기사 판정 대상 정보만 전달한다. 외부 API의 로그·보관 정책은 확인한다. |

### 사용자가 보는 흐름과 화면

1. **조건 입력:** V1과 동일한 조건을 입력한다.
2. **정량 추천 결과:** V1과 동일한 후보·점수·순위를 정량 근거와 함께 표시한다. 이 결과를 먼저 확정하고 뉴스 결과로 수정하지 않는다.
3. **추천 카드의 뉴스 영역:** 각 추천 ETF 이름으로 검색하고 직접 관련 판정을 통과한 기사만 표시한다. 기사별 제목, 발행일, 출처 링크를 제공한다.
4. **정상 검색 완료·관련 기사 없음:** 오류가 아니라 정상 완료 상태로 알리고 “직접 관련 기사가 없습니다”와 같은 빈 상태를 보여준다. 정량 결과는 계속 표시한다.
5. **뉴스 검색 또는 관련성 판정 실패:** 정상 빈 결과와 다른 실패 상태를 표시한다. 정량 결과·점수·순위는 계속 표시하고, 뉴스 재시도 가능 여부를 알린다. 실패 세분화 문구와 재시도 정책은 [확인 필요].
6. **기사 원문:** 사용자가 출처 링크를 선택하면 해당 출처의 원문 페이지를 연다. 새 탭 여부, URL 안전성/리디렉션 처리 등 세부 동작은 [확인 필요].

### Backend 처리 원칙

- V1의 입력 검증·KRX 데이터 계산·후보 필터·점수화·정렬을 먼저 수행한다.
- 정량 추천 결과의 ETF 목록과 이름을 뉴스 검색 대상으로 사용한다. 후보 풀 전체나 다음 순위 후보를 뉴스 때문에 확장하지 않는다.
- 검색/판정 API가 느리거나 실패해도 정량 응답을 반환한다. 뉴스 상태는 정량 결과와 분리된 부분 상태로 제공한다.
- 검색 결과를 Decisions API로 보내 사전 정의된 직접 관련성을 판정한다. 유사 ETF명, 다른 종목, 주제만 비슷한 기사, 대상이 모호한 기사는 노출하지 않는다.
- 직접 관련 판정을 통과한 기사에는 제목·발행일·원문 출처 URL을 연결한다. 누락/잘못된 URL, 발행일 형식 오류, 판정 불확실은 직접 관련 기사로 노출하지 않는다.
- API 응답·오류·타임아웃·호출 한도·부분 성공을 뉴스 상태로 구분하되, 외부 API 비밀값과 내부 상세 오류를 사용자에게 노출하지 않는다.
- 뉴스가 점수·적합성 문구·다음 후보 선정에 들어가지 않는지 회귀 검증한다.

## 7. 처리 흐름

| 순서 | 단계 | 설명 |

| 1 | V1 입력 검증 | 투자 조건을 V1 규칙으로 검증한다. 잘못된 입력이면 추천 및 뉴스 검색을 시작하지 않는다. |
| 2 | 정량 데이터 확인 | KRX 데이터 및 지표 상태를 확인한다. KRX 실패 처리 방식은 V1 요구사항을 따른다. |
| 3 | 정량 후보 산출 | 필터·점수·동점 처리·순위를 V1과 동일하게 수행한다. |
| 4 | 정량 결과 확정 | 동일한 입력/정량 데이터에 대해 V1의 후보·점수·순위를 유지한다. 정량 결과는 뉴스 상태와 독립적으로 출력 가능해야 한다. |
| 5 | 추천 ETF 이름별 검색 | 확정된 추천 목록의 각 ETF 이름으로 뉴스 검색 API를 호출한다. 기간 및 요청 수는 [확인 필요]. |
| 6 | 직접 관련성 판정 | 기사 후보를 Decisions API의 사전 정의된 기준으로 판정한다. 다른/유사 ETF나 대상을 특정할 수 없는 결과는 직접 관련에서 제외한다. |
| 7 | 뉴스 상태 구성 | 직접 관련 기사 있음, 정상 검색 완료·기사 없음, 검색 실패, 판정 실패를 구분한다. |
| 8 | 카드 출력·원문 열기 | 정량 결과와 이유에 뉴스 상태/기사 제목·발행일·출처 링크를 추가한다. 뉴스 실패에도 정량 결과를 유지한다. |
| 9 | 결과 이력 처리 | V1 추천 이력을 유지한다. 뉴스 이력을 저장·재조회할지는 결정 후 적용한다. |

## 제약과 데이터 취급

- V1의 원화 입력, 기간/성향 값, 산업 분류·데이터 기준과 기존 보관 제약을 유지한다.
- 정량 계산과 뉴스 조회는 분리한다. 뉴스 API 호출 실패가 V1 정량 추천을 취소하거나 대체하지 않는다.
- API 인증정보는 서버에서만 보관하고 프런트엔드, API 응답, 일반 로그에 기록하지 않는다.
- 뉴스 검색 API에는 검색에 필요한 ETF 이름/식별자만 전달한다. 투자금·투자성향·선호/제외 조건을 외부 뉴스/Decisions API에 전달하지 않는다.
- 기사 제목·발행일·출처 URL의 표시와 저장/캐시/원문 전달은 이용권, 저작권, 공급자 약관을 확인한 뒤 결정한다. 뉴스 원문을 복제하거나 요약하지 않는다.
- Decisions API가 제공하지 않은 근거나 확률을 임의로 만들어 기사 관련성을 사용자에게 설명하지 않는다. 불확실/오류는 직접 관련으로 취급하지 않는다.
- 외부 API에 기사 본문 등 추가 정보를 보내야 하는지, 전송·저장·로그 가능 범위는 [확인 필요]다.
- V2는 뉴스 기반 투자 조언, 매수·매도 지시, 수익 보장, 뉴스 감성/호재·악재 순위 반영을 제공하지 않는다.

## [가정]·[후순위]·[규제] 표시

- **[가정]** V2 뉴스는 정량 추천이 끝난 뒤 추천 목록에 대해서만 조회하며, 기사 정보는 정량 결과와 별도 영역으로 보여준다.
- **[가정]** “직접 관련” 여부는 서비스 자체 추론이 아니라 Decisions API의 미리 정해 둔 기준으로 판정한다. 판정 기준·버전·결과 스키마가 확인되기 전에는 실제 판정을 구현 완료로 간주하지 않는다.
- **[가정]** 직접 관련으로 판정된 기사 중 제목·발행일·원문 출처 URL이 유효한 기사만 카드에 표시한다. 조회 기간, 표시 수, 검색 정렬은 아직 정하지 않았다.
- **[후순위/V3]** 뉴스로 ETF 적합성을 판단하거나 순위·후보를 변경하고 다음 후보를 선택하는 기능은 V2에서 제외한다.
- **[규제·이용권 확인]** V1의 금융상품 비교 관련 규제 검토와 KRX 라이선스 검토를 유지한다. V2 추가로 뉴스 검색·기사 메타데이터 표시·원문 링크·Decisions API 전송 계약/저작권/약관 검토를 추가한다. 이 문서는 법률 적합성 판단이 아니다.
