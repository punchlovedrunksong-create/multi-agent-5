## 1. MVP 목표

| 항목 | 내용 |
| --- | --- |
| 프로젝트명 | angel ETF |
| MVP 한 줄 설명 | 사용자의 투자 조건을 받아 실제 KRX 자료와 연결된 ETF 후보를 비교하고, 근거·지표 기준일·출처를 보여주는 웹 서비스 |
| 검증할 핵심 가치 | 사용자가 예산·기간·선호/제외 조건·성향으로 매수 가능한 ETF 후보를 좁히고 실제 시장 자료에 기반한 비교 이유를 이해할 수 있는가 |
| 시연 방식 | 고정 테스트 자료로 규칙·예외를 재현한 뒤, 실제 KRX API를 조회해 수집된 자료로 동일한 입력→후보 비교→결과 표시 흐름을 시연 |

MVP 완료 시점에는 실제 KRX 자료를 사용한 결과가 나와야 한다. 고정 자료 시연은 규칙을 분리 검증하기 위한 것이며 실제 KRX 연동 완료를 대체하지 않는다. 사용자가 정한 방향에 따라 비교·점수·위험 판단에는 기존 API가 제공하는 정량 지표를 사용한다. 구체 API 필드와 지표는 KRX에 실제 연결해 확인하는 선행 작업에서 결정한다.

## 2. MVP 사용자 흐름

| 순서 | 사용자 또는 시스템 | 동작 |
| --- | --- | --- |
| 1 | 개발/데이터 담당 | 시스템 구성을 확정하기 전에 별도 기능 작업으로 최소 API 호출 클라이언트와 응답 확인 흐름을 만들어 실제 KRX API를 호출한다. 접근 권한, 응답 구조, ETF 필드·정량 지표, 기준일과 이용 조건을 확인한다. |
| 2 | 사용자 | 투자금, 투자 기간(1년 미만/1~3년/3~5년/5년 이상), 선택적 선호·제외 분류, 투자 성향(안정형/중립형/공격형)을 입력하고 비교를 요청한다. |
| 3 | 서비스 | 필수값과 입력 형식을 검증한다. 잘못된 입력이면 어느 항목을 고칠지 표시하고 비교를 중단한다. |
| 4 | Backend | 승인된 KRX 데이터와 기준일을 사용해 예산상 1주 매수 가능 후보를 필터링하고, 확인된 정량 지표와 합의된 규칙으로 비교·정렬한다. API가 제공하지 않는 값은 추정하지 않는다. |
| 5 | 서비스 | 후보가 있으면 최대 5개를 캐릭터형 카드/비교 화면에 보여주고 조건 일치 근거, 가격·지표, 정의·관측 구간·기준일·출처·한계를 표시한다. 후보가 없거나 자료가 부분/오래됨/오류이면 서로 다른 상태와 다음 행동을 안내한다. |
| 6 | 서비스 | 조건과 결과 스냅샷을 익명 브라우저 세션에 연결해 저장하고 생성 시각부터 7×24시간 보관한다. 같은 세션에서 재조회하고 만료 시 결과 만료 안내를 보여준다. |
| 7 | 사용자 | 저장된 비교 결과를 같은 브라우저 세션에서 다시 열어 당시 입력·순위·데이터 기준을 확인한다. |

세부 입력 한도, 산업 분류의 사용 가능 범위와 API 필드 매핑은 KRX 응답 확인 후 확정한다. MVP는 투자 주문이나 매수 지시를 하지 않는다.

| 2 | KRX 수집·검증·DB 적재 (F-02, F-03, F-10) | 승인된 ETF 자료를 수집하고 응답을 검증·정규화해 적재; 요청/수집 시각·출처·건수·오류·마지막 성공 기준일 기록 | 실제 ETF 후보를 만드는 데이터 공급 경로 |

| 4 | 예산 적격 후보 필터 (F-04) | 확인된 기준 가격이 투자금 이하인 후보를 선별하고 제외 조건을 적용; 가격/분류 확인 불가는 구분 | 사용자가 매수 가능한 후보를 찾는 문제를 해결 |
| 5 | 정량 지표 및 조건 비교 (F-05, F-06) | 실제 API 필드로 가능한 비교 지표를 정하고 기간·성향·조건에 적용; 누락 지표, 기준일, 점수/순위 근거 기록 | 실제 데이터 기반 결과와 설명 가능한 정렬에 필요 |
| 6 | 결과·오류 안내 화면 (F-08, F-09) | 최대 5개 캐릭터형 후보, 비교 근거, 지표 정의·관측 구간·출처·기준일·한계; 입력 오류·후보 없음·API 오류·오래된/부분 데이터 안내 | 사용자가 결과를 보고 오해 없이 다음 행동을 알 수 있음 |
| 7 | 익명 세션 결과 보관·재조회·만료 (F-07, F-12) | 결과 스냅샷을 익명 브라우저 세션에 연결하고 7×24시간 후 자동 만료·삭제 | 요구사항의 결과 재조회와 보관 정책을 만족 |
| 8 | 최소 운영 상태 확인·키 보호 (F-10, F-11) | 로컬 개발은 `.env`에서 Backend가 KRX 키를 읽고, `.env.example`에는 `KRX_API_KEY=your_krx_api_key_here` 같은 예시값만 둔다. `.env`는 `.gitignore`에 넣고 운영 배포에서는 호스팅 환경의 비밀 설정을 사용한다. 키는 Backend에서만 읽으며 프런트엔드·응답·일반 로그에 노출하지 않는다. | 실제 API 연동을 안전하게 확인하고 장애를 구분하기 위해 필요 |
| 9 | 실행·시연 README (R-05, R-07) | 설치·`.env.example` 복사 및 실제 `.env` 설정·실행·테스트 방법, 실제 KRX 연결 시 주의사항을 문서화 | 사용자가 재현 가능한 방식으로 V1을 실행·시연해야 함 |

뉴스 및 AI Agent는 사용자 요청에 따라 MVP에 포함하지 않는다. MVP의 비교 로직은 확정된 정량 지표와 명시적 규칙에 기반한 결정적 처리로 한정한다.

### 3.1 MVP 성향별 점수 규칙

공식 투자자 교육 자료는 위험 허용도와 투자 기간을 개인별로 함께 고려하며, 낮은 위험 선호는 원금 보전 성향, 높은 위험 선호는 손실 가능성을 감수하는 더 높은 잠재 수익 추구로 설명한다. 하지만 이 자료들은 ETF 후보 점수의 보편적인 수치 가중치를 제시하지 않는다. 따라서 아래 숫자는 “현재 시장의 표준”을 주장하는 값이 아니라 V1에서 일관되게 설명·검증하기 위한 초기 제품 규칙이다. [Investor.gov의 자산 배분·위험 허용도 설명](https://www.investor.gov/introduction-investing/getting-started/asset-allocation), [FINRA의 위험 허용도 설명](https://www.finra.org/investors/insights/know-your-risk-tolerance)

| 사용자 표시 성향 | 과거 수익률 | 변동성 안전도 | 최대 낙폭 안전도 | 적용 의도 |
| --- | ---: | ---: | ---: | --- |
| 안정형 | 20% | 35% | 45% | 과거 하락 폭과 가격 흔들림을 더 크게 반영 |
| 중립형 | 35% | 30% | 35% | 성장 지표와 두 위험 지표를 비교적 고르게 반영 |
| 공격형 | 55% | 20% | 25% | 과거 수익률 비중을 높이되 위험 지표도 점수에 유지 |

계산 원칙:

- 후보군 안에서 각 지표를 0~100 백분위 호감도로 바꾼다. 과거 수익률은 높을수록 점수가 높고, 변동성과 최대 낙폭은 낮을수록 안전도 점수가 높다. 동점은 중간 순위를 쓴다.
- 종합점수 = 수익률 호감도 × 성향 가중치 + 변동성 안전도 × 성향 가중치 + 최대 낙폭 안전도 × 성향 가중치. 성향별 가중치 합은 100%다.
- 세 핵심 지표 중 하나라도 결측/비교 불가라면 남은 지표만으로 가중치를 재분배하지 않는다. 그 ETF는 점수·순위를 “확인 불가”로 두고 누락 이유를 표시한다.
- 유효 후보가 하나뿐이면 상대 백분위 점수/순위를 산출하지 않고 단일 후보임을 표시한다. 종합점수 동점은 최대 낙폭이 낮은 후보, 변동성이 낮은 후보, ETF 코드 오름차순으로 정렬한다.
- 투자 기간은 API가 지원하는 관측 구간 중 선택한 기간에 가장 잘 맞는 구간을 고르는 데 사용한다. 기간 자료가 맞지 않으면 기간 비교를 지원하지 않는다고 표시하고 다른 구간을 동등한 자료처럼 취급하지 않는다.
- 이 점수는 후보군 안의 과거 데이터 비교 점수다. 개인의 전체 재정상황·손실 감내능력을 평가하지 않으며 투자 적합성·미래 수익을 보장하지 않는다.

이 규칙은 계산 가능성과 설명 가능성을 위한 MVP 출발점이다. 실제 API에 동등한 지표가 있는지, 기간별 비교가 가능한지는 사전 KRX 연결 작업에서 확인한다. 지표 정의가 다르면 의미가 매핑 가능한지 검토하고, 불가능하면 점수화를 보류한다.

## 4. MVP에서 제외할 기능

| 번호 | 기능 | 제외 이유 | 후순위 처리 방향 |
| --- | --- | --- | --- |
| 1 | 뉴스 수집·요약·감성 반영 | 사용자가 후속 버전으로 지정했으며 실제 자료 비교만으로 V1 핵심 흐름 검증 가능 | 뉴스 출처·권한·시점·인용과 추천 반영 기준을 별도 요구사항으로 정의 |
| 2 | AI Agent / 생성형 대화·설명 | 사용자가 후속 버전으로 지정; MVP에서는 정량 지표 기반의 규칙을 먼저 검증 | Agent 역할, 모델, 외부 데이터 전송, 근거·환각 검증 기준을 새로 정의 |
| 3 | 계정 로그인·기기 간 동기화 | 결과 조회는 익명 브라우저 세션으로 시작하기로 결정 | 다중 기기 조회 요구가 생기면 인증·동의·보관 정책 검토 |
| 4 | 증권사 계좌 연동 및 주문 | 핵심 문제는 비교 정보 제공이며 주문은 범위 밖 | 별도 규제·보안·사용자 요구 검토 후에만 범위 설정 |
| 5 | 실시간 시세·푸시 알림 | API 갱신 주기 및 실시간 제공 조건 미확정; V1 후보 비교에 필수 아님 | 권한·갱신 주기·알림 기준 확정 후 검토 |
| 6 | 보유 자산 기반 포트폴리오 최적화 | 개인 보유 자산 입력과 최적화는 핵심 요구 범위 밖 | 사용자 데이터와 평가 방법을 포함한 별도 요구사항 작성 |
| 7 | KRX 외 분류·구성 정보 연동 | 외부 데이터 권한·비용·출처가 확정되지 않음 | KRX 실제 필드 확인 후 꼭 필요한 누락 정보에 한해 권한 확인된 출처 조사 |
| 8 | 고급 관리자 대시보드·배포 자동화 | 첫 V1 시연의 핵심 사용자 흐름이 아님 | 운영 환경 확대 시 모니터링/배포 요구를 별도 계획 |

## 5. 구현 순서

| 순서 | 작업 | 결과물 | 확인 방법 |
| --- | --- | --- | --- |
| 1 | 별도 KRX 연결 기능 작업 수행 | 최소 호출 클라이언트(분리 실행 가능), 승인된 API 접근 확인, 비밀정보를 제거한 응답 예시, 필드/정량 지표·기준일·호출 조건 메모 | 실제 API 호출 성공/실패, 응답 구조와 허용된 이용 조건을 확인; 이 기능 작업의 결과를 기준으로 구조 설계 진행; 아래 실 API 테스트 참조 |
| 2 | 데이터 계약과 MVP 규칙 확정 | 입력/출력 계약, API 필드 매핑, 가격 기준·관측 구간·지표 매핑; 본 문서의 성향별 MVP 점수 규칙 | 명세와 응답 샘플 대조; 지표 의미가 다르거나 불명확하면 확인 불가로 남기고 점수/순위를 억지로 확정하지 않음 |
| 3 | 고정 자료 기반 비교 규칙 구현 | 조건 검증, 예산 필터, 지표 표시/비교, 상태 분기 로직 | T-FIX-01~04를 고정 fixture로 반복 실행; 실 API 의존 없이 기대값 재현 |

### V1 완성 시연 장면

1. 실행 안내에 따라 서비스를 시작하고, 화면에 API 연결/마지막 성공 기준일이 표시되는 것을 확인한다.
2. 사용자가 예산, 기간, 선택적 선호·제외 조건, 투자 성향을 입력한다.
3. 서비스가 실제로 조회·저장한 KRX 자료에서 예산에 맞는 ETF 후보를 산출한다.
4. 최대 5개 후보 카드에서 실제 가격과 확인된 정량 지표, 각 기준일·출처, 조건별 비교 이유를 보여준다. 확인 불가 지표는 빈칸을 임의 값으로 채우지 않고 사유와 함께 표시한다.
5. 결과를 같은 익명 브라우저 세션에서 다시 열어 당시 조건과 데이터 기준이 유지됨을 확인한다.
6. 짧은 예외 시연으로 잘못된 투자금 입력 또는 정상 후보 없음/API 장애 중 하나를 재현해, 오류와 정상 빈 결과가 구분되는 안내를 확인한다.

시연 전제: KRX API 접근 승인을 받았고 실제 데이터 표시/저장 이용 조건을 확인해야 한다. API가 제공하는 필드가 비교에 필요한 지표를 충분히 지원하지 않으면 그 제한을 화면에 표시해야 하며, 실제 API 연동 없이 fixture만으로 끝난 상태는 V1 완료로 간주하지 않는다.

### 7.2 실제 KRX 연결 테스트

실제 API 테스트에는 승인된 인증 설정을 사용하되 키 값을 문서·화면 캡처·일반 로그에 기록하지 않는다. API 서비스·GET·`basDd`·`AUTH_KEY` 헤더의 실제 호출은 통과했다. 추가 호출은 제한과 데이터 이용 조건을 확인하고 수행하며, 응답 샘플은 공유 전 비밀정보를 제거한다.

실제 호출에서 확인한 출력 필드는 `BAS_DD`, `ISU_CD`, `ISU_NM`, `TDD_CLSPRC`, `CMPPREVDD_PRC`, `FLUC_RT`, `NAV`, `TDD_OPNPRC`, `TDD_HGPRC`, `TDD_LWPRC`, `ACC_TRDVOL`, `ACC_TRDVAL`, `MKTCAP`, `INVSTASST_NETASST_TOTAMT`, `LIST_SHRS`, `IDX_IND_NM`, `OBJ_STKPRC_IDX`, `CMPPREVDD_IDX`, `FLUC_RT_IDX`다. 이는 일별 거래 응답의 필드 목록 확인이며, `IDX_IND_NM`은 기초지수명으로 받아 ETF 산업/테마 분류와 동일하다고 간주하지 않는다. 변동성·최대 낙폭 등은 이 한 번의 호출에서 직접 반환되지 않았다.

### 성향별 비교 정책 결정

성향은 **안정형·중립형·공격형**, 초기 가중치는 각각 **20/35/45, 35/30/35, 55/20/25**(수익률/변동성 안전도/최대 낙폭 안전도)로 정했다. 투자 기간은 점수 가중치 대신 가장 맞는 가용 관측 구간 선택에 반영한다. 숫자는 공개된 보편 기준이 아니라 V1의 제품 규칙이다. 필드·기간 자료는 실제 KRX 연결 작업에서 확인하고 의미가 일치하지 않으면 임의 매핑하지 않는다.

근거와 한계: [Investor.gov](https://www.investor.gov/introduction-investing/getting-started/asset-allocation)와 [FINRA](https://www.finra.org/investors/insights/know-your-risk-tolerance)는 위험 허용도와 시간 지평이 개인의 목표·손실 감내능력에 따라 함께 고려되어야 한다고 설명하지만, 위 ETF 점수 비율을 정하지 않는다. 따라서 이 MVP 점수는 비교 기준을 설명하기 위한 상대 순위이며 개인별 투자 적합성 판단은 아니다.

- 판정: **보완 필요**
- 근거: V1 목표, 포함/제외 기능, 구현 순서, 시연 장면과 분리 테스트를 정리했다. 실제 인증 GET은 성공해 응답 행/필드를 확인했으나 데이터 정규화·저장·추천·화면 통합, API 이용 권한·호출 범위와 지표 매핑은 남아 있어 V1은 미완료다.
- 실행 검증: **부분 실행.** T-KRX-01 통과(2026-11-21, 두 기준일 모두 HTTP 200 JSON, 1,190행/1,155행, 필드 19개); 나머지 테스트는 미실행. 키와 시장 데이터 본문은 출력·문서화하지 않았다.
- 다음 권장 작업: 확인된 필드 계약으로 정규화·고정 자료 테스트를 만들고, 과거 날짜 자료와 이용 조건을 확인한 뒤 DB 및 후보 비교 흐름에 연결한다.
