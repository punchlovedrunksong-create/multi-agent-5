## 2. 기능 분해표

우선순위는 요구사항의 Must와 MVP 포함 여부를 기준으로 한다. 사용자가 확인한 방향은 기존 API가 제공하는 정량 지표를 비교·점수 및 산업/테마 조건 판단 근거로 사용하는 것이며, 결과 재조회 식별 방식은 익명 브라우저 세션이다. API 이름·필드·기준과 세션 보호 세부사항 등 아직 확정되지 않은 계약은 임의로 고정하지 않는다.

### 2.1 기능 간 흐름과 의존성

`F-02 → F-03 → F-04 → F-05 → F-06 → F-07 → F-08` 순으로 데이터가 전달된다. `F-01`은 사용자의 비교 요청에서 `F-04`와 `F-06`의 입력이 되며, `F-09`는 각 단계의 진행·실패 상태를 사용자에게 전달한다. `F-10`은 `F-02/F-03`의 운영 이력을 조회하고, `F-11/F-12`는 수집·결과 보관 흐름을 보호한다.

계약상 데이터 연결은 다음과 같다.

| 생산 기능 | 출력 계약 | 소비 기능 |
| --- | --- | --- |
| F-01 | `ComparisonRequest { amountKrw: number, period: enum, preferredCategories: enum[], excludedCategories: enum[], riskProfile: enum }` | F-04, F-06, F-07 |
| F-03 | `ETFMarketRecord { etfCode: string, status, referencePrice, priceAsOf, source, collectedAt }`와 `DataQuality` | F-04, F-05 |
| F-04 | `EligibleCandidate { etfCode, eligibility, exclusionReason?, priceAsOf }` | F-05, F-06 |
| F-05 | `MetricSet { return, volatility, maxDrawdown, observationPeriod, asOf, formulaVersion, availability }` | F-06, F-07, F-08 |
| F-06 | `RankedCandidate { etfCode, rank, score?, reasons[], metrics, dataVersion }` | F-07, F-08 |
| F-07 | `RecommendationResult { resultId, anonymousSessionId, requestSnapshot, candidates[], createdAt, expiresAt, version }` | F-08, F-09 |

위 필드명은 구현 전 합의할 논리 계약의 초안이며, 구체 DB 형식·API 직렬화 방식은 구조 설계 단계에서 확정한다. 제공되지 않은 가격·지표·분류는 값으로 대체하지 않고 `availability`와 사유로 표현한다.

## 3. API 기능 목록

경로는 기술 스택 미정 상태의 후보 이름이다. 익명 브라우저 세션 사용은 결정되었으며, 세션 토큰/쿠키 보호와 만료 세부 규칙, 운영 권한, 실제 HTTP 메서드와 응답 표준은 구조 설계 전 확인한다.

| 기능 | Endpoint 후보 | 설명 | 우선순위 |
| --- | --- | --- | --- |
| ETF 비교 요청 | `POST /api/recommendations` | 조건 검증, 후보 산출·정렬, 스냅샷 저장을 연결하고 결과 ID/결과를 반환 | 높음 |
| 저장 결과 조회 | `GET /api/recommendations/{resultId}` | 식별·접근 권한 및 만료 여부 확인 후 당시 저장 결과 반환 | 높음 |
| ETF 데이터 수집 실행 | `POST /api/admin/etl/runs` (후보) | 권한 있는 운영자가 승인된 수집 작업을 실행 | 중간 |
| 수집/서비스 상태 조회 | `GET /api/admin/status` (후보) | 마지막 성공 시각, 수집 상태·오류·건수와 데이터 기준일 제공 | 중간 |
| 만료 자료 정리 | 내부 스케줄 작업 (Endpoint 불필요 후보) | 만료 시각이 지난 결과와 조건 스냅샷 삭제 및 실행 이력 기록 | 중간 |

## 4. AI Agent 기능 목록

| Agent 기능 | 입력 | 처리 | 출력 | 우선순위 |
| --- | --- | --- | --- | --- |
| MVP AI Agent | 해당 없음 | 요구사항서에서 생성형 AI 설명 대화를 MVP에서 제외하고, 비교는 산식·규칙 기반으로 한정함 | AI가 생성한 추천/설명 없음; 확정된 계산 근거를 UI에서 표시 | 적용 안 됨 |

추후 “AI 설명 대화”는 별도 요구사항으로 다룬다. 모델, 사용자 데이터 외부 전송 여부, 답변 범위와 검증 방식이 미정이므로 현 기능이나 API 계약에 포함하지 않는다.

## 6. 추천 구현 순서

| 순서 | 기능 | 이유 |
| --- | --- | --- |
| 1 | F-02, F-03 KRX 수집·검증·적재 | 데이터 공급 가능 필드·권한 확인이 추천 기능의 선행 조건 |
| 2 | F-01 투자 조건 입력·검증 | 비교 요청의 입력 계약을 고정 |
| 3 | F-04 적격 후보 필터 | 투자금·가격·제외 조건을 적용할 수 있어야 함 |
| 4 | F-05 지표 산출 | 비교/정렬 이전에 지표 정의와 원천 자료가 필요 |
| 5 | F-06 조건 비교·정렬 및 근거 | 점수·기간·성향 기준 승인 후 구현 |
| 6 | F-07 결과 스냅샷·재조회·만료 | 결과의 시점별 재현과 7일 보관을 구현 |
| 7 | F-08 화면 표시와 F-09 상태 안내 | 사용자가 후보, 이유, 출처와 예외를 해석하도록 함 |
| 8 | F-10~F-12 운영·보안·만료 정리 | MVP 운영에 필요한 상태 확인, 키 보호, 보관 정책을 연결 |

이 순서는 선행 데이터·규칙이 합의된 경우의 개발 권장 순서다. 화면 골격은 F-01과 병행할 수 있으며, KRX 접근/이용 권한과 추천 산식이 미확정인 동안 실제 데이터 기반 비교 결과를 확정하지 않는다.
